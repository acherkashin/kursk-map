# Обогащение мест

## Назначение

Этот скилл помогает подготовить один или несколько объектов для карты лучших мест Курской области. По умолчанию сначала собери проверяемые данные, покажи готовый GeoJSON feature, источники и уверенность.

Если пользователь прямо просит добавить, записать, подключить или сохранить место в карте, определи целевую подборку:

- `featured` -> `src/featured-objects.json`, дефолтный набор без query-параметра;
- `all` -> `src/all-objects.json`, открывается через `?dataset=all`;
- `dozapravka` -> `src/dozapravka-objects.json`, открывается через `?dataset=dozapravka`;
- другая существующая подборка -> соответствующий `src/<slug>-objects.json`, если она найдена и подключена;
- новая подборка -> новый файл `src/<slug>-objects.json` в том же формате `FeatureCollection` и подключение в `src/data.ts` через `?dataset=<slug>`.

Если целевая подборка не названа, используй `src/all-objects.json` как безопасный вариант по умолчанию и явно сообщи об этом.

## Рабочий процесс

1. Уточни исходный запрос: название места, населенный пункт или район, если они есть в сообщении пользователя.
2. Сначала найди все коллекции `src/*-objects.json` и проверь уже существующие данные проекта, чтобы не создать дубль.
3. Найди место по официальным и публичным источникам. Приоритет источников:
   - официальный сайт или официальные соцсети объекта;
   - `gokursk.ru`;
   - сайты органов власти, музеев, учреждений, туристических порталов;
   - Wikimedia Commons, Wikidata, OpenStreetMap;
   - картографические сервисы только как вспомогательная проверка.
4. Проверь, что объект находится в Курской области. Если это не подтверждается, остановись и явно напиши, что данных недостаточно.
5. Подготовь нормализованные поля: название, адрес, координаты, категорию, описание, URL и изображение.
6. Верни результат как готовый GeoJSON feature и отдельный блок источников. Если часть данных спорная, не скрывай это: отметь поле как требующее ручной проверки.
7. Если пользователь попросил именно добавить или подключить место, запиши готовый feature в конец массива `features` целевой подборки и сообщи, как проверить ее в приложении.

## Координаты

- В проекте координаты хранятся в порядке `[lat, lon]`, не `[lon, lat]`.
- Строка `properties.balloonContent.coordinates` должна повторять тот же порядок: `"lat, lon"`.
- Округляй координаты до 6 знаков после запятой, если источник не требует большей точности.
- Если источники расходятся, предпочитай официальный источник объекта или проверенную точку на карте; при заметном расхождении укажи это в блоке источников.
- Яндекс Геокодер можно использовать только при наличии API-ключа и соблюдении лицензии. Не сохраняй результаты Яндекса в репозиторий, если нет подтверждения, что лицензия разрешает хранение и изменение данных.

## Описание

- Пиши на русском, нейтрально и без рекламной интонации.
- Опирайся только на найденные факты. Не выдумывай историю, услуги, режим работы, цены или особенности.
- Оптимальная длина: 1-2 предложения для карточки карты.
- Если фактов мало, лучше короткое честное описание, чем насыщенный, но неподтвержденный текст.

## Изображение

- Используй только изображения, которые можно обоснованно хранить в репозитории или ссылать в карточке.
- Приоритет:
  - Wikimedia Commons или другой источник с понятной открытой лицензией;
  - официальный сайт/страница объекта, если условия позволяют использовать изображение;
  - `gokursk.ru`, если объект уже представлен там и URL подходит текущему формату проекта;
  - локальный placeholder, если права неясны.
- Не скачивай и не сохраняй изображения из Яндекс Карт без явно подтвержденной лицензии.
- Если изображение безопасно использовать, поле `image` может быть внешним URL или локальным путем. Для нового локального файла путь должен быть вида `/place-thumbnails/<file>.webp`.
- Если права неясны, используй:
  - `image`: `/place-thumbnails/placeholder.svg`
  - `thumbnail`: `/place-thumbnails/placeholder.svg`
  - в источниках напиши, что нужна ручная замена изображения.

## Формат результата

Возвращай объект в формате существующих JSON-коллекций:

```json
{
  "type": "Feature",
  "id": 2000,
  "geometry": {
    "type": "Point",
    "coordinates": [
      51.730361,
      36.192647
    ]
  },
  "properties": {
    "type": "категория",
    "id": 2000,
    "balloonContent": {
      "url": "https://example.com/place",
      "image": "/place-thumbnails/placeholder.svg",
      "name": "Название места",
      "description": "Краткое проверенное описание места.",
      "address": "Курская область, адрес или ориентир",
      "coordinates": "51.730361, 36.192647",
      "button": "Открыть подробности",
      "thumbnail": "/place-thumbnails/placeholder.svg"
    }
  }
}
```

## Выбор подборки

Перед записью определи `targetDatasetSlug` и `targetCollectionPath`.

Правила:

- Если пользователь говорит "в полный список", "в all", "в dataset=all" или не называет подборку, используй `targetDatasetSlug = "all"` и `src/all-objects.json`.
- Если пользователь говорит "на главную", "в featured", "в дефолтную подборку" или "в короткий набор", используй `targetDatasetSlug = "featured"` и `src/featured-objects.json`.
- Если пользователь говорит "в do zapravka", "в dozapravka" или "в подборку дозаправка", используй `targetDatasetSlug = "dozapravka"` и `src/dozapravka-objects.json`.
- Если пользователь называет другую существующую подборку, найди файл `src/<slug>-objects.json` и используй его.
- Если пользователь просит создать новую подборку, предложи человекочитаемый латинский slug в `kebab-case`, например `family-routes`, `museums`, `weekend`, и создай `src/<slug>-objects.json`.

Не смешивай режимы: добавление места в `all` не означает автоматическое добавление в `featured` или тематические подборки. Добавляй место в несколько подборок только если пользователь прямо попросил это сделать.

## Запись в существующую подборку

В режиме добавления в уже существующую подключенную подборку редактируй только ее JSON-файл. Не меняй `src/data.ts`, если подборка уже подключена и открывается через существующий query-параметр.

Алгоритм записи:

1. Прочитай все `src/*-objects.json`.
2. Проверь дубли во всех подборках по `id`, `properties.id`, нормализованному `name`, близким координатам и совпадающему адресу.
3. Если найден вероятный дубль, остановись и покажи найденный объект вместо добавления нового.
4. Выбери новый `id` как следующий свободный номер после максимального `id`/`properties.id` во всех коллекциях.
5. Установи одинаковый `id` в корне feature и в `properties.id`.
6. Добавь feature в конец массива `features` в целевом JSON-файле.
7. Сохрани валидный `FeatureCollection` без изменения структуры остальных объектов.
8. После записи укажи URL проверки:
   - для `featured`: локальное приложение без `dataset`;
   - для остальных подборок: `?dataset=<slug>`.

Не добавляй новое место в другие подборки, если пользователь не попросил это отдельно.

## Создание новой подборки

Создавай новую подборку только если пользователь прямо попросил новую подборку, новый dataset или отдельный набор мест.

Алгоритм:

1. Выбери `slug` в латинице, в `kebab-case`, без пробелов и спецсимволов. Если название неоднозначно, предложи slug сам и продолжай.
2. Убедись, что `src/<slug>-objects.json` еще не существует.
3. Создай `src/<slug>-objects.json` как валидный `FeatureCollection`:

```json
{
  "type": "FeatureCollection",
  "features": []
}
```

4. Добавь подготовленные features в `features`.
5. Подключи файл в `src/data.ts`:
   - импортируй `src/<slug>-objects.json`;
   - добавь ветку в `getSelectedRawCollection()`, чтобы `?dataset=<slug>` возвращал новую коллекцию;
   - оставь `featured` дефолтом.
6. Если новая подборка становится поддерживаемым пользовательским режимом приложения, обнови `AGENTS.md`: добавь ее в список dataset-режимов и структуру проекта, если это уместно.
7. Сообщи URL проверки: `?dataset=<slug>`.

Не меняй формат JSON-объектов и не вводи реестр dataset-ов без явной необходимости. Для одной новой подборки достаточно прямого импорта и ветки в `getSelectedRawCollection()`, как в текущем коде.

## Правила полей

- `id`: если редактирование JSON не запрошено, предложи следующий безопасный id после проверки существующих id. Для ручного черновика можно указать `TODO_ID`.
- `properties.type`: используй существующую категорию, если она очевидна по проекту; иначе короткую русскую категорию вроде `"музей"`, `"природа"`, `"спорт и отдых"`, `"агротуризм"`.
- `url`: предпочитай официальный URL или страницу с подробностями. Если надежной страницы нет, используй найденный публичный источник и отметь ограничение.
- `image`: локальный путь или внешний URL, который проект сможет нормализовать. При сомнениях ставь placeholder.
- `thumbnail`: локальный путь из `/place-thumbnails/` или placeholder.
- `button`: для официальной подробной страницы используй `"Узнать подробнее"`, для внешних справочников или соцсетей — `"Открыть подробности"` или `"Открыть сообщество"`.
- `name`: правильное публичное название объекта без лишних SEO-добавок.
- `address`: не оставляй пустым. Если точного адреса нет, укажи район, населенный пункт или ориентир и пометь как требующий проверки.

## Обязательный блок после GeoJSON

После каждого подготовленного feature добавляй:

```markdown
Источники и уверенность:
- Название: источник, уверенность высокая/средняя/низкая.
- Координаты: источник, уверенность высокая/средняя/низкая.
- Адрес: источник, уверенность высокая/средняя/низкая.
- Описание: какие факты использованы.
- Изображение: источник и правовой статус; если placeholder, почему.
- Ручная проверка: что нужно проверить перед добавлением в JSON.
```

## Ограничения

- Не добавляй npm-зависимости для этой задачи.
- Не меняй формат `src/featured-objects.json`, `src/all-objects.json`, `src/dozapravka-objects.json` и других `src/*-objects.json`.
- Не меняй `src/data.ts` для уже подключенных подборок без необходимости. Меняй `src/data.ts` только при создании новой подборки или если пользователь явно просит подключить существующую неподключенную подборку.
- Не меняй пайплайн `scripts/generate-thumbnails.mjs` без отдельного согласования.
- Не скачивай и не сохраняй изображения из Яндекс Карт без явно подтвержденной лицензии.
- Не добавляй app tests для самого скилла: это не runtime-код приложения. После реального добавления места запускай `npm run build` или `npm run test` только если пользователь отдельно подтвердил проверку.
